# pyramid\_max: спецификация стратегии

Nov 18, 2026 · @Борис

## Цель и принципы

pyramid\_max ждёт импульс после разворота и набирает пирамиду по максимуму; на боковике и флэте прибыль копить не должна. Описание для лонга на M15 (ТФ не фиксирован), шорт зеркально.

- Нет стопов, трейлинга, шагов прибыли и частичных тейков.
- Один стек. Base — самый нижний уровень (для лонга), все остальные уровни — расширения. Понятия «текущая пирамида» нет, BE всегда считается по всему стеку.
- Все уровни одного размера q. Предела числа уровней нет.
- Риск нижних уровней гасится следующими базами на старших ТФ (M15, H1, H4, H12 и далее) по логике recovery из pyramid\_2.
- Закрытие только в небольшой плюс с учётом комиссий; убыток нигде не фиксируется.

## Режимы PROFIT и RECOVERY

Режим определяется порядком создания уровней, а не ценой: по состоянию стека (цены, объёмы, плюс или минус) растущую пирамиду с откатом и стек после неудачных баз не различить, различается только история.

- **PROFIT**: время создания самого нижнего уровня (Base) самое старое среди всех уровней стека. Всё остальное выросло из этой базы.
- **RECOVERY**: иначе, то есть выше Base есть уровни, открытые раньше неё. Значит, Base открывалась ниже прежних уровней, когда цена шла против нас.
- В StackElem добавляется поле `opened_at` (время создания). Уровни без него (из старого сохранённого состояния) считаются самыми старыми. Равные значения времени разрешаются порядком в списке.
- Пока в стеке есть старые убыточные уровни, работает recovery из pyramid\_2 целиком, а логика PROFIT из этой спецификации не применяется. Пирамида строится заново только после того, как старые уровни погашены.
- Переход в PROFIT происходит сам: когда остаётся один уровень или самый нижний снова самый старый.

Отдельно существует проверка «цена выше BE стека» (`PyramidModeResolver`). Она нужна только для выхода по развороту, режим не определяет.

## Вход

Base открывается по HA breakout, расширения только по цене: HA-сигнал для расширений не используется.

- **Base**: по HA breakout, когда стек пуст или как новая нижняя база в recovery (ниже всех существующих уровней, с проверкой дистанции `step_ratio` до каждого уровня). Открытие любой Base стирает Take Profit.
- **Расширение**: открывается, когда цена ушла вверх от верхнего уровня на текущий шаг (для лонга: ask ≥ верхний уровень + шаг).
- **Шаг** не хранится: он равен расстоянию между двумя самыми верхними уровнями стека. Если уровень один, шаг равен исходному d = `step_ratio` × цена.
- Повторного входа на одном пробое нет: после открытия верхний уровень сам сдвигается вверх на шаг.

Как шаг растёт сам после схлопываний (d — исходный шаг):

| Схлопываний | Шаг (расстояние между верхними уровнями) |
| --- | --- |
| 0 | d |
| 1 | 1,5 d |
| 2 | 2,25 d |
| 3 | около 3,4 d |

Шаг только растёт и обратно не уменьшается. Идеи с возвратом шага и с учётом глубины отката обсуждались и пока отложены.

## Схлопывание верхней пары

Первые два уровня (Base и первое расширение) не схлопываются и держатся при любом откате. Схлопывание начинается с третьего уровня.

- Условие: цена откатила к BE верхней пары уровней (для лонга: bid ≤ BE пары с учётом комиссий, в небольшой плюс).
- Действие: верхняя пара закрывается, и на этой цене сразу открывается один новый уровень q (реарм). Объём стека уменьшается на q, Base остаётся внизу.
- После схлопывания расстояние между новым уровнем и уровнем под ним равно 1,5 прежнего шага. Это и есть новый шаг (шаг выводится из стека, отдельно не хранится).
- Закрытие в убыток запрещено: пара закрывается только при BE выше нуля с учётом комиссий.

Цена этого решения: откат на половину шага уже запускает цикл с комиссиями, во флэте они постоянно утекают. Растущий шаг эту утечку сокращает, потому что схлопываний становится меньше.

## Выходы

В PROFIT два выхода, и каждый закрывает весь стек целиком. Стек закрывается по тому из них, что случится раньше.

1. **Take Profit** — цена из конфига, задаётся вручную. Параметра нет — выхода по тейку нет. При открытии любой Base (на любом ТФ) цель стирается, при старте с пустым стеком цель убирается с предупреждением. Для достижения цели: bid ≥ цена (лонг).
2. **Разворот** — HA breakout вниз на ТФ стека, зеркальный сигналу входа. Закрывает стек, только если цена выше BE стека (с комиссиями). Условие по уровню, не по краю: если сигнал уже активен, а цена ниже BE, стек ждёт и закрывается при первом возврате выше BE. Если разворот случился, попытка закончена; выход с микроприбылью считается удачей.

Если стек в минусе, сигнал разворота игнорируется, никаких других выходов нет. Риск гасится recovery со старших ТФ. Стопов, шагов прибыли и частичных тейков нет.

## RECOVERY из pyramid\_2

Recovery из pyramid\_2 (`pyr_recovery_mode.py`) подходит без изменений: в нём нет стопов и шагов прибыли, и он совместим с остальной схемой.

- **Base** здесь самый нижний уровень. Новая Base открывается по HA breakout только ниже всех существующих уровней, с проверкой дистанции `step_ratio` до каждого уровня.
- **Компенсация**: когда нижний уровень ушёл в плюс (с учётом `min_pnl`), он закрывается целиком вместе с убыточными уровнями выше цены, начиная с самых убыточных, пока хватает его прибыли. Всё закрывается примерно в ноль.
- После закрытия Base делается REARM: новый уровень q по текущей цене.
- Остаток стека (недогашенный старый уровень и реарм-уровень) продолжает работать в RECOVERY, пока самый нижний уровень не самый старый. Когда старых уровней не остаётся, режим сам становится PROFIT и начинается новая пирамида.
- Переключение ТФ после открытия Base (лестница M15, H1, H4, H12) сохраняется.

В RECOVERY нет выхода по тейку и по развороту, и схлопывание не применяется.

## Цены для проверок

Лимитные ордера выставляются на активную часть спреда и исполняются сразу, поэтому условие проверяется по цене той стороны, по которой исполнится ордер (для лонга; шорт зеркально).

| Событие | Цена (лонг) |
| --- | --- |
| Откат к BE верхней пары (схлопывание) | bid |
| Выход по развороту, определение «в плюсе» | bid |
| Take Profit | bid |
| Открытие расширения при проходе шага | ask |
| Реарм после схлопывания | ask |

В `PyramidStrategy.resolve` цена закрытия уже берётся через `get_market_close_price` (Buy: bid, Sell: ask). Для открытия нужна противоположная сторона, готового метода в `market_service.py` нет, его нужно добавить. Новый уровень после схлопывания встаёт по ask, а пара закрылась по bid, разница равна спреду.
