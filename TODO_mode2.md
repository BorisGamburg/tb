# Pyramid 2 — Режим 2: Recovery (цена не лучше BE стека)

Режим 2 активен, когда цена не лучше безубыточности (BE) всего стека:
Buy — цена ≤ BE, Sell — цена ≥ BE. Определяется `PyramidModeResolver` на каждом цикле заново.

В режиме работают два самостоятельных механизма:

1. Компенсация: закрытие нижнего уровня и части убыточного уровня с последующим REARM.
2. Открытие нового нижнего уровня по HA Breakout.

## 0. Определение Base

Base — всегда нижний уровень стека:

- Buy — уровень с минимальной ценой входа.
- Sell — уровень с максимальной ценой входа.

При открытии нового нижнего уровня Base смещается на него. Когда цена вернётся в режим 1,
прежний Base станет обычным Extension и будет закрываться по шагу. Это принятое поведение.

## 1. Компенсация

### 1.1. Источник прибыли

Прибыль берётся только с нижнего уровня (Base).

Используется существующий параметр `step` стратегии (`open_step_pct`).

**Buy:** условие выполнено, если `Bid >= Entry Price × (1 + step)`

**Sell:** условие выполнено, если `Ask <= Entry Price × (1 - step)`

Entry Price — цена входа нижнего уровня. Если условие не выполнено, компенсации нет.

### 1.2. Кандидаты на закрытие

- Кандидаты — убыточные уровни, кроме нижнего. Убыток считается на монету по текущей
  цене закрытия с учётом комиссий.
- Прибыльные уровни кандидатами не являются.
- Порядок перебора: от уровня с наибольшим убытком на монету к уровням с меньшим убытком.

### 1.3. Проверка достаточности прибыли

Для кандидата проверяется, что прибыли нижнего уровня (с учётом комиссий) за вычетом
`min_pnl` хватает на закрытие хотя бы `min_qty` этого кандидата (с учётом `qty_step`).

- Берётся первый кандидат, для которого проверка пройдена.
- Если кандидат не найден, компенсации в этом цикле нет, переходим к механизму 2.

### 1.4. Объём закрытия

- Нижний уровень закрывается целиком.
- С кандидата закрывается максимальный объём, который покрывается прибылью нижнего
  уровня при итоге не ниже `min_pnl`, округлённый вниз по `qty_step`, но не больше
  остатка кандидата.

### 1.5. Частичное исполнение

- Из уровней списывается только фактически закрытый объём.
- Остаток сохраняется в стеке.
- REARM при частичном исполнении не выполняется.
- Никаких специальных повторных попыток закрытия нет.

### 1.6. REARM после компенсации

Если закрытие исполнено полностью, сразу в том же цикле выполняется REARM по общей схеме:

1. Проверка дистанции: расстояние от текущей цены до каждого уровня стека не меньше `step`.
2. Если дистанция не подходит, REARM пропускается. Повторных попыток в следующих циклах нет.
3. Объём берётся из `open_checker.get_qty()` (`open_qty_pct`).
4. Если ордер не исполнен, он повторяется, пока не исполнится.

### 1.7. Если REARM пропущен

В стеке остаются только убыточные уровни, нижнего прибыльного уровня нет, и компенсация
не запускается. Новый нижний уровень появится через механизм 2.

## 2. Открытие нижнего уровня по HA Breakout

### 2.1. Сигнал

Используется уже реализованный механизм HA Breakout. Его алгоритм не меняется.

### 2.2. Условие «самый нижний»

Новый уровень открывается, только если он будет самым нижним в стеке:

- Buy — цена входа (Ask) ниже цены входа любого существующего уровня.
- Sell — цена входа (Bid) выше цены входа любого существующего уровня.

Иначе открытие не выполняется.

### 2.3. Проверка дистанции

Расстояние от текущей цены до каждого уровня стека не меньше `step`
(существующая `is_level_distance_allowed`).

### 2.4. Объём

`open_checker.get_qty()` (`open_qty_pct`).

### 2.5. Что не проверяется

- Буфер BE: усреднение вниз приближает BE к цене, проверка не нужна.
- Тренд (`HATrendChecker`).
- Лимит позиции (`is_position_limit_allowed`): пока не проверяется, вернёмся позже.

### 2.6. Ошибки открытия

При любой ошибке открытия выбрасывается исключение. Дополнительной обработки ошибок,
повторных попыток и сохранения сигнала нет.

## 3. Общий порядок выполнения режима 2

Каждый цикл выполняется в следующем порядке:

1. Проверить условие компенсации (нижний уровень ушёл на `step`, прибыли хватает
   на кусок убыточного уровня).
2. Если условие выполнено, закрыть нижний уровень и кусок убыточного уровня.
3. Если закрытие полное, сразу выполнить REARM с проверкой дистанции.
4. Если в цикле произошла компенсация (полная или частичная), завершить обработку режима.
   HA Breakout не проверять.
5. Если компенсации не было, проверить HA Breakout.
6. Если сигнал есть, уровень будет самым нижним и дистанция позволяет, открыть уровень.

### Ограничения на торговые действия

В обычном цикле допускается не более одной торговой операции.

Единственное исключение — связанная последовательность:

**Полное закрытие (компенсация) → REARM.**

Закрытие имеет приоритет над открытием.

## 4. Сводная таблица правил

| Механизм | Правило |
|---|---|
| Активация режима | Цена не лучше BE стека |
| Base | Нижний уровень (Buy — min цена, Sell — max цена) |
| Источник прибыли | Только нижний уровень |
| Условие Buy | Bid ≥ Entry × (1 + step) |
| Условие Sell | Ask ≤ Entry × (1 − step) |
| Кандидаты на закрытие | Убыточные уровни, кроме нижнего |
| Порядок кандидатов | От наибольшего убытка на монету к меньшему |
| Достаточность прибыли | Хватает на ≥ `min_qty` кандидата при итоге ≥ `min_pnl` |
| Объём закрытия | Нижний уровень целиком + максимально покрываемый кусок кандидата |
| Частичное исполнение | Списывается факт, остаток в стеке, REARM не делается |
| REARM | После полного закрытия, с проверкой дистанции |
| Повтор REARM | Если ордер не исполнен, повторяется до исполнения; пропуск по дистанции не повторяется |
| Объём REARM и открытия | `open_checker.get_qty()` |
| HA Breakout | Открытие самого нижнего уровня |
| Проверка дистанции | Обязательна при открытии и REARM |
| Буфер BE, тренд, лимит позиции | Не проверяются |
| Приоритет | Компенсация выше HA Breakout |

**Итог:** режим 2 использует прибыль нижнего уровня, ушедшего на шаг от входа, чтобы
сократить самые убыточные уровни, и после полного закрытия восстанавливает нижний уровень
через REARM. Если нижнего уровня нет, он открывается по HA Breakout. Дискретность задаётся
шагом цены от входа нижнего уровня: после REARM новый нижний уровень сбрасывает условие.

## 5. Отложено и открытые вопросы

- Лимит позиции в recovery (сейчас не проверяется).
- Мигание режимов около BE: нужен ли гистерезис.
- Способ исполнения связки: один ордер на суммарный объём (как в старом unwind) или два
  ордера, и как распределяется исполнение при частичном заполнении.
- Старый код в `pyramid_strategy.py` (`_process_open`, `_process_close`, `_try_rearm`
  со свёртыванием) в новой логике, скорее всего, не нужен: решить, удалять ли.
