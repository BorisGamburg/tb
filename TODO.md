## Pyramid 2 — новая логика управления стеком

### 1. Открытие уровней
- Первый уровень открывается по обычному сигналу ENTRY.
- Второй уровень открывается на стандартной дистанции одного шага от первого, без проверки буфера.
- Начиная с третьего уровня, перед открытием проверяется достаточность буфера с учётом нового суммарного BE.
- Все уровни имеют одинаковый размер.
- Новый уровень может открываться выше или ниже предыдущего. Важны его положение относительно всего стека и условия открытия.

### 2. Base и Extension
- Base — самый нижний уровень для Buy и самый верхний для Sell.
- Base определяется исключительно по цене открытия относительно остальных уровней стека.
- Статус Base динамический: при появлении более экстремального уровня Base определяется заново.
- Все остальные уровни являются Extension.
- Base не закрывается обычным механизмом фиксации прибыли по шагу.

### 3. Закрытие Extension
- Extension закрывается с прибылью, когда цена проходит от его цены открытия один шаг в благоприятном направлении.
- После закрытия выполняется попытка REARM.
- REARM открывает новый уровень, только если среди оставшихся уровней нет другого в пределах допустимой дистанции.

### 4. Unwind — два режима работы

**Режим A. Полное закрытие по безубытку**
- Когда суммарный результат стека достигает безубытка, Unwind пытается закрыть весь стек.
- Если из-за изменения цены или частичного исполнения остаётся небольшой остаток, операция всё равно считается полным закрытием по BE.
- REARM не выполняется.
- Оставшийся объём должен быть закрыт отдельно. Новый ENTRY возможен после полного закрытия позиции и появления нового сигнала.

**Режим B. Частичная свёртка убыточного стека**
- Если стек находится в убытке, прибыль доступных уровней используется для компенсации убытков остальных уровней.
- Закрывается максимально возможная часть убыточной позиции с учётом фактического результата и комиссий.
- Возможны полное и частичное закрытие отдельных уровней.
- После исполнения Unwind выполняется попытка REARM.
- REARM открывает новый уровень только при отсутствии близких уровней в пределах допустимой дистанции.

Тип операции Unwind определяет необходимость REARM. Она не должна определяться только по фактическому количеству оставшихся контрактов.

### 5. REARM
- После частичной свёртки выполняется немедленная попытка REARM.
- Если стек закрыт полностью по BE, REARM запрещён, даже если после исполнения остался небольшой технический остаток.
- После обычного закрытия Extension также выполняется попытка REARM.
- Новый уровень открывается только при соблюдении проверки дистанции.

### 6. Завершение и начало нового цикла
- После полного закрытия стека по BE стратегия ожидает нового сигнала ENTRY.
- Новый цикл начинается с открытия первого уровня.
- Автоматическое восстановление прежнего количества уровней не выполняется.

### 7. Что убрать из старой реализации
- Старую логику Unwind, не соответствующую двум новым режимам закрытия.
- Старую логику REARM, если она противоречит новым правилам.
- Автоматическое восстановление количества уровней.
- Dust Close.
- Устаревшие проверки и параметры, которые больше не нужны новой модели.

### 8. Что сохранить и проверить
- Существующие компоненты расчёта частичного закрытия, если они подходят новой логике.
- Корректный учёт фактически исполненного объёма после частичных закрытий.
- Пересчёт состава стека после каждой операции.
- Однозначный приоритет Unwind и обычного закрытия Extension, чтобы один уровень не участвовал одновременно в двух операциях.
