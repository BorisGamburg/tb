# Pyramid 2 — Режим 1: Stack PnL > BE

Режим 1 активен, когда суммарный PnL стека превышает безубыточность (BE).

В режиме работают два самостоятельных механизма:

1. Пошаговое закрытие Extension с последующим REARM.
2. Дополнительное открытие уровней по HA Breakout.

## 1. Пошаговое закрытие Extension

### 1.1. Какие уровни участвуют

- Base никогда не закрывается этим алгоритмом.
- Обрабатываются только Extension.
- При выполнении условия закрывается один Extension целиком.
- Если условие одновременно выполнено для нескольких Extension, можно выбрать любой. Приоритета по расстоянию от Base нет.

### 1.2. Условие закрытия

Для каждого Extension проверяется достижение одного шага прибыли относительно цены входа конкретного уровня.

Используется существующий параметр `step` стратегии.

**Buy:**

Закрываем уровень, если:

`Bid >= Entry Price + step`

**Sell:**

Закрываем уровень, если:

`Ask <= Entry Price - step`

Таким образом, используется Bid для Buy и Ask для Sell. Проверка выполняется по цене, реально доступной для закрытия позиции.

### 1.3. Объём закрытия

- При выполнении условия отправляется закрытие всего оставшегося объёма Extension.
- Если исполнение частичное, с уровня списывается только фактически закрытое количество.
- Остаток уровня сохраняется в стеке.
- Никаких специальных повторных попыток закрытия или дополнительных действий не предпринимается.
- За один цикл закрывается не более одного Extension.

### 1.4. REARM после закрытия

REARM является частью алгоритма пошагового закрытия.

Если Extension закрыт полностью:

1. Сразу в том же цикле выполняется попытка REARM.
2. Используется существующая логика расчёта объёма REARM.
3. Выполняется существующая проверка дистанции REARM.
4. Если дистанция не подходит, REARM пропускается.
5. Повторных попыток REARM в следующих циклах нет.

Если закрытие исполнено частично, REARM не выполняется.

Закрытие Extension и REARM представляют собой связанную последовательность, поэтому в одном цикле допускаются два торговых действия.

### 1.5. Приоритет

Пошаговое закрытие имеет приоритет над HA Breakout.

Если в текущем цикле произошло закрытие Extension:
- выполняется REARM, если условия позволяют;
- HA Breakout в этом цикле больше не проверяется.

Если ни один Extension не закрылся, можно переходить к проверке HA Breakout.

---

## 2. Дополнительное открытие по HA Breakout

HA Breakout — самостоятельный механизм открытия дополнительного уровня. Он не зависит от того, сколько уровней было восстановлено через REARM.

### 2.1. Проверка сигнала

Используется уже реализованный механизм определения HA Breakout.

Его алгоритм не меняется.

### 2.2. Проверка буфера

При наличии сигнала HA Breakout перед открытием нового Extension обязательно проверяется достаточность буфера с учётом изменения безубыточности всего стека.

Порядок проверки:

1. Моделируем открытие нового Extension.
2. Рассчитываем новый BE всего стека с учётом нового уровня, торговых комиссий и прочих затрат, влияющих на безубыточность.
3. Получаем текущую цену активной стороны спреда — ту же сторону, по которой будет выставлен лимитный ордер:
   - Buy — Ask.
   - Sell — Bid.
4. Рассчитываем процентное расстояние от текущей цены до нового BE.

**Buy:**

`buffer_pct = (Ask - New BE) / Ask * 100`

**Sell:**

`buffer_pct = (New BE - Bid) / Bid * 100`

5. Сравниваем полученное значение с отдельным параметром `min_be_buffer_pct`.

- Если `buffer_pct >= min_be_buffer_pct`, открытие разрешено.
- Если `buffer_pct < min_be_buffer_pct`, открытие запрещено.

Новый BE должен находиться на правильной стороне текущей цены и иметь минимальный запас, заданный параметром `min_be_buffer_pct`.

Если буфера недостаточно:
- открытие не выполняется;
- сигнал не сохраняется;

### 2.3. Выполнение открытия
Если буфер достаточен, выполняется попытка открытия дополнительного уровня.

При любой ошибке открытия выбрасывается исключение.

Дополнительной обработки ошибок, повторных попыток и сохранения сигнала нет.

---

## 3. Общий порядок выполнения режима 1

Каждый цикл выполняется в следующем порядке:

1. Проверить условия пошагового закрытия Extension.
2. Если условие выполнено — закрыть один Extension.
3. Если закрытие полное — сразу выполнить REARM с проверкой дистанции.
4. Если в цикле произошло закрытие Extension — завершить обработку режима 1. HA Breakout не проверять.
5. Если ни один Extension не закрылся — проверить HA Breakout.
6. Если сигнал есть — проверить достаточность буфера с учётом нового суммарного BE.
7. Если буфер достаточен — попытаться открыть дополнительный уровень.
8. Если буфера недостаточно — пропустить сигнал.

### Ограничения на торговые действия

В обычном цикле допускается не более одной торговой операции.

Единственное исключение — связанная последовательность:

**Полное закрытие Extension → REARM.**

В этом случае в одном цикле допускаются две операции.

Закрытие имеет приоритет над открытием. Одновременное выполнение пошагового закрытия и HA Breakout не допускается.

## 4. Сводная таблица правил

| Механизм | Правило |
|---|---|
| Активация режима | Stack PnL > BE |
| Пошаговое закрытие | Только Extension |
| Base | Не закрывается |
| Условие Buy | Bid ≥ Entry + step |
| Условие Sell | Ask ≤ Entry − step |
| Источник step | Существующий параметр стратегии |
| Объём закрытия | Весь остаток Extension |
| Частичное исполнение | Списывается фактически закрытый объём |
| Количество закрытий | Не более одного Extension за цикл |
| Выбор уровня | Любой подходящий Extension |
| REARM | Сразу после полного закрытия |
| REARM после частичного закрытия | Не выполняется |
| Проверка дистанции REARM | Существующая логика |
| Повтор REARM | Нет |
| HA Breakout | Отдельный механизм открытия |
| Буфер HA Breakout | Обязательная проверка нового суммарного BE |
| Недостаточный буфер | Сигнал пропускается |
| Ошибка открытия | Без повторных попыток |
| Приоритет | Закрытие Extension выше HA Breakout |

**Итог:** режим 1 позволяет последовательно фиксировать прибыль по Extension при движении цены на один шаг от цены входа каждого уровня, восстанавливать полностью закрытые уровни через REARM и дополнительно открывать уровни по HA Breakout при достаточном буфере стека. Base остаётся вне механизма пошагового закрытия.
